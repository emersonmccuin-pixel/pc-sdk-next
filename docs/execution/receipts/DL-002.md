## Delivered invariant

Unlanded repository work can be removed only after a browser-only explicit
approval binds a fresh strict preview to the exact contract version, producer,
repository identity, owned worktree row/path, branch/tip/base/integration
evidence, and tracked plus deterministic untracked content digest. The request
cannot author actor, authority, repository, path, branch, or receipt fields;
the server derives user/browser attribution after same-origin, JSON, UUID,
typed-confirmation, version, digest, and live-evidence validation.

Authority is an immutable contract receipt committed with its outbox event
before teardown. The durable `abandoning` state means approval exists but
settlement is incomplete. Teardown shares the repository FIFO and lease with
landing, never runs cleanup-profile commands, removes only the approved owned
worktree, preserves the feature branch at its exact approved tip, and records
final `abandoned` only after positive directory and Git-registration absence.
Boot recovery re-drives that exact receipt. Uncertainty remains retryable and
visible; elapsed time never implies success.

Landing, continuation, review, runtime disposal, and abandonment use exact
one-winner fences. DB triggers/CAS prevent late child admission or generic
landing mutation after authority exists. Reviewer cleanup is compare-and-clear
and shared per reviewer. Post-terminal work is tracked; shutdown drains task
producers to a fixed point and propagates cleanup uncertainty.

Legacy `abandoned` contracts with no receipts stay readable, visible,
non-destructive, and protected from orphan cleanup. No generic landing setter,
chat command, orchestrator/specialist tool, MCP route, or prompt can mint
abandonment authority.
