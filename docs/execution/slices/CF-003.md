# CF-003: Durable send and interruption control

Status: verified; ready for guarded landing

## Objective

Implement the accepted `CHAT-005` and `CHAT-006` semantics as one coherent
conversation/turn-control slice: queued sends survive restart as a visible FIFO
with immutable revision snapshots at delivery, and interrupt-and-send cannot
release its replacement message without a positive terminal interruption
receipt.

## Requirements and boundaries

- Requirement IDs: `ARCH-005`, `CHAT-001`, `CHAT-002`, `CHAT-004`, `CHAT-005`,
  `CHAT-006`, `REC-001`, `UI-001`
- Boundary documents: `docs/architecture/boundaries.md`,
  `docs/architecture/chat-communications.md`,
  `docs/agent-runtime-architecture.md`
- Conversations own durable messages, queue state/revisions, canonical sequence,
  and replay. Turns own the one-active-turn interruption lifecycle. Runtime
  adapters only execute the typed interrupt request.
- Every durable queue/interrupt transition and its canonical notification must
  commit atomically. DB rows are truth; sockets, coordinators, and UI are
  projections.

## Scope

In scope:

- durable queue items and append-only text revisions with session FIFO position,
  unique client idempotency identity, origin metadata, CAS edit/remove commands,
  and a delivery-revision snapshot that becomes immutable at `delivering`;
- canonical sequenced queue-state events plus connect snapshots, using one
  browser projection for live/replay/reconnect;
- user and typed agent-envelope turns through the same durable coordinator,
  without exposing agent-envelope transport text as editable user content;
- boot recovery that re-drives queued rows, fails uncertain `delivering` rows
  loudly, and never re-sends an accepted/uncertain turn by inference;
- durable interrupt request/confirmed/failed transitions tied to the target turn;
- interrupt-and-send admission that atomically links a queued replacement to its
  request, releases only after an `aborted` turn terminal, and fails closed on
  request/runtime/restart uncertainty;
- sender command receipts, visible FIFO/edit/remove UI in the existing composer
  shell, and typed interruption feedback derived from server state;
- contract, migration/repository, server race/recovery, browser projection, and
  end-to-end guard tests.

Out of scope:

- manual queue reordering, retry policy for failed queue items, scheduled sends,
  or a general workflow/state-machine engine;
- safe operational activity and complete tool lifecycle (`CHAT-007/008`);
- runtime/account/model/effort selection, adapter capability discovery, or Codex;
- visual redesign, notification-center work, or changes to repository delivery;
- provider smoke or changes to native interrupt semantics.

Implementation evidence required four safety amendments without changing the
accepted product behavior: queue execution is gated on composition readiness;
session/account/project lifecycle writes are atomic with FIFO cancellation;
deleted projects cannot admit or claim work; and pre-account-switch sessions
remain viewable but are non-resumable until immutable runtime/account stamps
land. These close paths that could otherwise violate criteria 4, 6, and 7; they
do not implement the N3 runtime selector.

## Acceptance criteria

1. Admission is idempotent per `(sessionId, clientMessageId)` and commits the
   queue row, revision 1, canonical queue event, and outbox entry atomically.
2. FIFO order is durable. Edit creates a revision only while `queued`; remove is
   fail-closed outside the documented undelivered states; CAS mismatch is typed.
3. Claiming `delivering` snapshots one revision. Later edit/remove cannot alter
   the text actually sent to the runtime.
4. Queued rows survive process loss and drain without a browser connection.
   Rows that were `delivering` at restart fail loudly and are never inferred
   accepted or sent a second time.
5. Agent envelopes retain their typed metadata and delivery order across restart
   while remaining non-editable and safely summarized in the user queue view.
6. Interrupt requested/confirmed/failed are durable canonical control events.
   Only an `aborted` terminal for the exact target turn confirms the request.
7. A linked interrupt-and-send item cannot be claimed before confirmation; a
   failed or uncertain request prevents replacement delivery and surfaces why.
8. Live, replay, reconnect snapshot, duplicate commands, and shuffled canonical
   delivery converge to one visible queue/interruption projection.
9. The existing visual shell gains a compact queue with edit/remove actions and
   honest interruption feedback; it does not add a new product surface.
10. Focused contract/DB/server/web checks, recovery/race tests, independent audit,
    and `pnpm ci:check` pass.

## Risk and recovery

- Risks: duplicate turn delivery after crash, queue row/event divergence,
  revision mutation after claim, an interrupt request confirmed by a normal
  terminal, or internal agent envelopes becoming editable/leaking raw transport
  text.
- Recovery: fail uncertain transitions loudly; keep blocked replacement rows
  undelivered; preserve the CF-001 event/outbox and CF-002 projector path; any
  failed invariant leaves this branch/worktree intact and landed `main` clean.
