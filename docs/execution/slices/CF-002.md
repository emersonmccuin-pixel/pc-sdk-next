# CF-002: Canonical projector scale

Status: in-progress

## Objective

Remove the canonical browser projector's per-event full-history scan/copy/sort/
re-derive behavior for normal ordered delivery, and compact completed stream
delta payloads from presentation state, without changing the CF-001 wire,
persistence, ordering, replay, or fail-closed conflict semantics.

- Requirement IDs: `ARCH-005`, `CHAT-002`, `CHAT-003`, `CHAT-004`, `UI-001`
- Boundary documents: `docs/architecture/boundaries.md`,
  `docs/architecture/chat-communications.md`
- Required behavior: server sequence remains authoritative; prior projector
  states remain immutable/branchable; exact duplicates are no-ops; conflicts
  preserve the accepted sequence projection; live and replay converge.

## Scope

In scope:

- persistent/indexed canonical event, sequence, stream/item, and delta receipts;
- incremental projection for monotonically sequenced live events;
- one explicit normalization path for shuffled/out-of-order replay checkpoints,
  with frontier buffering rather than live-history rebuilds;
- completed-stream compaction that retains enough identity evidence to detect
  exact redelivery and later conflicts without retaining every delta payload in
  render state;
- deterministic operation-count/state-size characterization rather than
  machine-fragile wall-clock thresholds;
- browser reducer/store/render tests and as-built documentation updates.

Out of scope:

- any conversation contract, server, database, relay, or migration change;
- delta coalescing at the producer/persistence layer;
- durable send queue/edit/remove, interruption receipts, safe activity/tool
  lifecycle, runtime selection, or Codex;
- visual redesign.

- `apps/web/test/chat-store.test.ts`, `apps/web/test/chat-render.test.ts`
- `docs/event-contract.md`, `docs/current-state.md`, `docs/execution/**`

## Acceptance criteria

1. Ordered live delivery uses indexed identity checks and incremental aggregate/
   stream transitions; it does not scan or sort the full accepted history for
   each event.
2. A deterministic large ordered stream characterization records zero fallback
   rebuilds, retains bounded presentation history while active, and releases
   completed delta payloads after the stable item lands.
3. Exact event and delta redelivery remains a no-op. Conflicting sequence,
   event, stream/item, or delta identity remains explicit and fail-closed even
   after stream compaction.
4. Shuffled live events and replay converge to the same frames, projected
   frames, aggregates, stream buffers, conflicts, and high-water state as
   server-order delivery.
5. Applying an event never mutates any previously returned projector state;
   branching from an earlier state remains deterministic.
6. Past-session and live timelines continue to consume the same projected
   state and the existing visual shell is unchanged.
7. Focused web tests, workspace typecheck, and `pnpm ci:check` pass.

  evidence, arrival-order-dependent stream binding, or replay divergence.
- Recovery: keep the CF-001 database/wire untouched; any failed invariant keeps
  this branch/worktree preserved and leaves landed `main` unchanged.
