# CX-002: Provider-free Codex runtime-adapter conformance

Status: implementation sealed and feature-tree verified; guarded landing
pending

## Objective

Implement the provider-local `CodexRuntimeAdapter` and canonical runtime-session
mapping against the checked stable app-server 0.144.1 protocol, exercised only
through an injected provider-free peer. Prove the public adapter contract for
account-scoped discovery, exact native create/resume receipts, ordered text
turns, interruption semantics, terminal closure, typed unavailable telemetry,
and disposal without registering Codex or authorizing a native thread or turn.

This is the mapping and conformance layer that a later contained native client
may satisfy. It is not a discovery-only adapter whose required session methods
throw after successful preflight, and it is not evidence that the current
native app-server can safely execute PC-SDK work.

## Provider-free execution boundary

The adapter has no default native runtime-peer factory. Construction requires
explicit injected discovery and runtime peers plus an independent conformance
authority, and production composition does not import or instantiate it. The
authority must attest a closed execution-policy receipt before a thread request;
the execution peer cannot attest itself. In CX-002 the only admitted receipt is
labelled provider-free conformance and proves facts about the fake peer only:
the pinned stable protocol, empty effective native-tool and MCP sets, no
approval requests, closed method/event vocabulary, and contained fake
lifecycle. The same independent authority atomically seals each fake turn epoch
before attesting its terminal boundary. Neither receipt is ever accepted as
evidence about an OS process or a real Codex configuration.

Missing, malformed, production-labelled, stale, mismatched, or partially
supported policy evidence refuses the thread request. A nonempty app tool
bridge, native-tool allowlist, interactive ask handler, or unsupported input
also refuses before the peer can create a thread. This design prevents the
provider-free mapping from becoming a hidden live-execution path while leaving
one provider-local port for a later mechanically enforced native peer.

Pinned stable 0.144.1 currently provides no complete positive effective-tool
inventory or empty-MCP receipt. Approval policy controls prompting, not whether
ordinary sandbox-permitted actions can run, and read-only still permits reads.
MCP startup can occur while a thread starts. Therefore no native peer can mint
the required production policy receipt in this slice.

## Canonical session semantics

Create and resume capture the full selection, attempt id, requested native id,
cwd, instructions, limits, and policy before any await. They re-run the shared
selection preflight immediately before peer mint. Resume uses only
`thread/resume` with the exact requested id; any mismatch or failure is typed
unavailable and never retries as create.

The response, not a notification or schema presence, supplies the positive
native attachment fact. The adapter validates the exact thread id, admitted
built-in provider, selected model and effort, cwd, and provider-free policy
echo before constructing a session. Its first successful turn yields one
provider-neutral `session-started` receipt bound to the exact selection,
attempt, mode, native id, and requested resume id.

`turn/start` returns the sole active native turn id. Only frames matching the
exact thread, turn, and admitted agent-message item may affect the canonical
stream. Public agent text maps to message start/deltas/end and one completed
assistant block. Private reasoning, native ids, inputs, outputs, diffs, native
error prose, account identity, and arbitrary metadata never cross the adapter.

`turn/completed` is the sole native terminal source. Completed maps to success,
interrupted to aborted, and failed to a fixed redacted error. Malformed order,
unknown or mismatched identities, conflicting/duplicate terminal frames,
warning/error notifications, server requests, approval requests, command/file/
MCP/dynamic/collaboration items, or post-terminal frames fail closed through
exactly one canonical error terminal. No partially observed native action is
called safe execution.

An accepted `turn/interrupt` response acknowledges only the command. The
correlated later interrupted terminal proves abort. Disposal is idempotent,
settles the exact fake peer, and prevents late frames from affecting a newer
turn or session.

## Acceptance criteria

1. `CodexRuntimeAdapter` implements the existing public interface with exact id
   `openai-codex`, but no production source outside `runner/codex/**` imports it
   and `apps/server/src/index.ts` remains byte-for-byte unchanged.
2. Account identity, capability states, model ids, labels, descriptions,
   resolved ids, and supported effort values are strictly normalized and
   defensively copied. Missing/malformed discovery is typed unavailable; no
   alternate account, model, effort, runtime, credential, or billing path is
   attempted.
3. Provider-free execution cannot begin without an exact fake-only policy
   receipt. The real 0.144.1 path is explicitly unable to produce a production
   tool/MCP/approval/containment receipt and starts no thread or turn.
4. Create and resume revalidate an immutable selection after every relevant
   await. Resume requires exact identity and never falls back to create.
5. Thread response mismatch across id, requested id, provider, model, effort,
   cwd, approval/reviewer, sandbox, or policy refuses before a canonical
   session receipt.
6. Each session admits one active turn. Exact response/notification correlation,
   ordering, duplicate/conflict fencing, and disposed/stale-session behavior
   are provider-free and deterministic.
7. A successful text turn yields one exact session receipt, ordered canonical
   text events, and exactly one success terminal. Native ids and payloads are
   absent from every event.
8. Failed, interrupted, malformed, tool/MCP/approval-bearing, warning, request,
   and race paths each close through exactly one fixed safe terminal; private
   reasoning and provider prose are never surfaced.
9. Interrupt acceptance is not terminal proof. Only the exact later correlated
   interrupted terminal yields canonical `aborted`.
10. Context and quota stay typed unavailable with exact runtime/account
    attribution; token-usage notifications do not invent context or quota.
11. Disposal is idempotent, exact-peer scoped, and fences late events. CX-001's
    admission-only client, executable/environment policy, and direct-child
    lifecycle tests remain unchanged and green.
12. The same public conformance harness runs against Codex, Claude, and a
    generic fake for applicable create/resume receipt, turn-terminal,
    interruption, mutation, and disposal invariants.
13. Codex-native method vocabulary stays provider-local; static guards prove
    no composition, registration, selector, contract, browser, or alternate
    transport path was added.
14. Focused tests, exhaustive stable-item/server-request classification,
    source/actual-path audits, `git diff --check`, hostile review, full
    `pnpm ci:check`, production web build, sealed commit, guarded landing,
    ancestry/tree proof, post-merge gate, exact push/re-fetch, and worktree
    teardown pass.

## Risk and recovery

- Main risks: accidentally turning a fake mapping into a native execution
  door, treating approval routing as tool denial, accepting a mismatched resume,
  leaking native payloads/reasoning, emitting multiple terminals, or weakening
  the admission-only CX-001 client.
- Recovery: every unsupported or uncertain peer, policy, protocol, identity,
  ordering, interruption, or disposal state fails closed. No native thread is
  created, and the isolated worktree is preserved on uncertain verification or
  landing.
- Positive escaped-descendant containment requires a separate product/toolchain
  decision because the honest Windows mechanism is an in-process native Job
  Object spawn binding plus Windows CI; Node's direct child, `taskkill`, and PID
  enumeration are insufficient. That decision is not hidden in CX-002.
