# CX-001: Pinned Codex app-server subscription path

Status: active — contract defined; implementation not yet started

## Objective

Prove the first bounded N5 dependency: PC-SDK can launch an exactly pinned
Codex app-server through the hardened child boundary, positively observe the
cached ChatGPT auth kind in one exact existing credential home, reject effective
custom-provider/catalog routing, discover the built-in advertised model/effort
surface, and repeat those observations through a positively stopped and
restarted native process. Preserve the version-matched stable protocol and a
reusable JSONL client for a later `CodexRuntimeAdapter`, without claiming fresh
entitlement or model usability, registering a partial adapter, starting a model
turn, or changing product selection behavior.

## Canonical spike semantics

The checked-in generated schema comes from the exact local package binary,
without `--experimental`. Generated types are evidence and provider-local
authority; they are never copied into browser-safe or provider-neutral
contracts. Any package upgrade must deliberately regenerate and re-review the
schema and repeat this spike.

The client sends one `initialize` request, validates the returned exact
`codexHome`, explicitly declares `experimentalApi: false` and
`requestAttestation: false`, then sends `initialized` before any other method.
Pinned 0.144.1's initial `remoteControl/status/changed` snapshot is admitted
only when status is `disabled` and `environmentId` is null; server name and
installation identity are discarded. Requests have
unique locally minted IDs. A duplicate, unknown, malformed, oversized, late,
or conflicting response cannot settle another request. EOF, timeout, stderr
overflow, child exit, or protocol corruption yields typed unavailable evidence
and rejects every pending request. Server-initiated requests never hang: this
slice refuses them explicitly, and any such request fails the spike because no
live thread or turn is authorized.

The live command never infers its home. It first requires the app-server to
identify its exact selected home, then requires stable `account/read` to report
cached ChatGPT auth kind and `config/read` to prove the effective catalog is not
custom-routed. It does not inspect credential files or print account identity.
It does not set `forced_login_method`; official behavior can log out a
mismatched home. Normal token refresh, app-server startup, or model discovery
may update native caches in the selected credential home, so the slice does not
claim byte-level home immutability.

The live gate proves only exact-home cached ChatGPT-auth-kind observation,
built-in advertised model/effort discovery, and positive native process
restart. Credential freshness, entitlement, actual subscription usability,
billing route, and model usability remain unavailable. It sends no `thread/*`
or `turn/*` request and therefore makes no model-inference claim. Raw frames,
email/account identity, native IDs, provider error prose, token/quota values,
and reasoning remain absent from durable evidence. Stable `warning`,
`guardianWarning`, `configWarning`, `windows/worldWritableWarning`,
`deprecationNotice`, and `error` notifications all fail, as does any stderr
byte. Any auth/config mismatch, enabled remote control, server request,
unexpected thread/turn/tool activity, catalog disagreement, ambiguous default
model/effort, or missing stable method stops without retry or alternate billing.

## Acceptance criteria

1. The repo pins exactly `@openai/codex@0.144.1`; the executable reports exact
   `codex-cli 0.144.1`, and no product path resolves ambient `codex` from PATH.
2. The non-experimental generated TypeScript tree, command, version, inventory,
   and hash are committed; clean regeneration from the pinned package is exact.
3. Codex-native vocabulary is confined to `runner/codex/**`, its thin script,
   tests, and documentation. No production registration or product selector
   changes.
4. Provider-free tests prove handshake order, concurrent/out-of-order request
   correlation, notifications, fragmented lines, bounded frames/timeouts,
   malformed/duplicate/unknown responses, server requests, early child exit,
   stderr redaction/limits, and idempotent process-tree disposal.
5. A fake child captures the final environment and proves the shared SEC-003
   allowlist plus exactly the selected `CODEX_HOME`; ambient raw credentials,
   endpoints, peer homes, Git selectors, and app variables are absent.
6. The live command refuses missing/noncanonical/nonexistent homes and requires
   explicit live-provider consent. It never chooses or retries another home.
7. Cached ChatGPT auth-kind and non-custom effective config evidence are
   positive before model discovery. API-key, Bedrock, missing/malformed auth,
   custom provider/catalog/endpoint routing, or unavailable evidence performs no
   discovery or model turn and exposes only stable redacted failure codes.
8. Stable built-in advertised discovery produces one visible default model
   whose default reasoning effort is present in its supported set; the spike
   uses those returned values without creating a product default.
9. The live client sends no thread, turn, login, logout, tool, MCP, approval,
   context, quota, or inference request; an unexpected server request or
   thread/turn/tool notification fails the gate.
10. The first app-server positively stops. A distinct second native process
    repeats exact-home cached ChatGPT-auth-kind and config-provenance checks and
    returns the same unambiguous built-in default model/effort observation.
11. Both native processes are absent, disposable schema paths are removed, and
    the durable receipt contains only redacted version/schema, auth-kind,
    model/effort, exact-restart-catalog-match, and cleanup facts.
12. Credential freshness, entitlement, billing route, model usability, native
    create/resume, terminal turns, interruption, approvals, tools/MCP, context,
    rate-limit normalization, canonical mapping, and dispatch behavior remain
    explicitly unavailable/inconclusive rather than inferred from cached auth,
    catalog, or schema presence.
13. Focused tests, source/actual-path audits, `git diff --check`, hostile
    review, full `pnpm ci:check`, production web build, sealed commit, guarded
    landing, ancestry/tree proof, post-merge gate, exact push/re-fetch, and
    worktree teardown pass.

## Risk and recovery

- Main risks: schema drift, ambient CLI/home/API fallback, an auth mismatch that
  mutates login state, private/native payload leakage, request mis-correlation,
  launcher/native-child orphaning, false restart/catalog agreement, and scope
  drift into a tool-capable live turn without a pre-execution guard.
- Recovery: all uncertain protocol/process/auth/discovery states fail closed;
  provider work stops on a warning, and no native thread is created. A failed
  gate leaves this isolated worktree preserved for explicit inspection. No
  cleanup command targets the credential home.
