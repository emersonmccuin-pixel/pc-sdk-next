# RS-002: Honest per-session context observation

Status: verified and sealed; pending guarded landing

## Objective

Implement the bounded N3 context invariant for orchestrator app sessions: the
composer shows current context use only from a positive adapter observation,
with exact/derived/approximate/unavailable confidence and visible compaction
evidence. Live delivery, reconnect replay, and cold session replay must converge
through the existing canonical conversation/outbox path without a second
snapshot store.

## Canonical decisions

`ContextObservation` is a closed union. Available observations carry safe
integer counts satisfying
`0 <= usedTokens <= usableTokens <= contextWindowTokens`, plus `exact`,
`derived`, or `approximate` confidence. Unavailable observations carry no token
values or percentage and use `confidence: unavailable` plus one closed reason:
`unsupported`, `runtime-unavailable`, `invalid-observation`, or
`observation-timeout`. The browser computes bar fill from the accepted counts;
it does not accept a provider's rounded percentage as independent truth.

The pinned Claude SDK `Query.getContextUsage()` response is the only Claude
current-context control source. The adapter also retains only the latest
primary assistant iteration's input/cache receipt. A valid final message or
fallback iteration supplies the exact current numerator as of the last model
request; it intentionally replaces the control response's stripped top-level
total for multi-iteration tool loops. Without that correlation—including
resumed history—the validated control total is derived, whether it came from
`apiUsage` or native category tokenization. Invalid non-null evidence fails
closed; malformed or missing primary/sidechain ownership cannot preserve older
exact evidence. A compact boundary clears pre-boundary exact evidence before
the out-of-turn return, while a later valid primary assistant may restore it.
`maxTokens` is the effective usable limit and `rawMaxTokens` is retained
canonically as the raw context window. Receipt time is observation time and is
retained across persistence retries; raw native timestamps are unavailable.

Existing SDK `result.usage` is turn execution telemetry, not current context.
It is forbidden as context evidence even when its input/cache fields resemble
a prompt size. The existing turn-usage event continues only when all token
fields are valid; malformed evidence yields no usage event, and ambiguous
multi-model attribution is null.

Context observation is a stable telemetry event on the same conversation
sequence/outbox as every other canonical event. It is tied to an existing
settled turn, and persistence rejects a second observation for that turn. The
terminal and idle projection commit first; the bounded observation attempt then
records exactly one available/unavailable event before the FIFO successor may
begin. A new turn or compaction makes the prior observation visibly stale until
new evidence arrives. Any later canonical frame positively attributed to a
different turn also stales immediately, including while it is buffered above a
sequence gap. Latest folded turn evidence prevents a later older-turn
observation, superseded turn identities cannot roll the epoch backward, and
receipt-time event-ID conflicts fail closed before a gap can drain. Pending
identities and context mutations use bounded immutable indexes rather than
history scans. Timeout/failure becomes explicit unavailability. A crash or
disposal before the attempt can persist leaves prior evidence explicitly stale;
a late response from a timed-out, disposed, or replaced runtime writes nothing.

Compaction remains orthogonal control evidence. Its closed event uses
`manual | auto | unknown` trigger and nullable pre/post counts, so the latest
known compaction edge remains visible beside the context bar even when metadata
or current-use observation is unavailable. Counts, when present, are
non-negative safe integers. Malformed metadata produces no invented
`auto`/zero claim. Context-capability unavailability never rejects selection/
create/resume, fails a turn, or triggers runtime/billing fallback.

The browser keeps context readiness separate from send/session readiness. A new
session or no session has an authoritative empty projection; historical resume
waits for a valid replay. A valid replay or folded context/compaction event
establishes context readiness. Queue snapshots cannot do so. Only a fresh
available observation renders a percentage; stale, loading, compacted, and
unavailable states show no current fill or percentage.

## Acceptance criteria

1. Runtime capabilities explicitly state context-current-use confidences and
   compaction-observation support. Every runtime session implements the typed
   observation command; missing support is explicit and never affects runtime
   selection or turn success.
2. Claude current context comes only from a strictly validated
   `getContextUsage()` control receipt. Raw native categories, paths, tool names,
   native percentages, and exception text never cross the adapter seam.
3. Exact and derived Claude observations preserve current tokens, effective
   usable limit, raw window, and confidence. Malformed, thrown, timed-out, or
   unavailable observations contain no fabricated token values.
4. Every normally settled eligible orchestrator turn records exactly one
   available/unavailable context observation with the same session/turn
   attribution before its FIFO successor starts. Persistence rejects duplicates.
   A crash/disposal before persistence leaves prior evidence stale; a reminted,
   switched, timed-out, or late runtime cannot update a successor.
5. Context observation commits through the canonical conversation event/outbox
   transaction. Live delivery, reconnect replay, shuffled/redelivered frames,
   and cold replay converge without a new table/channel or duplicate effects.
6. Context readiness is independent of queue/session readiness. A newer turn
   and compaction mark prior context stale until newer evidence arrives;
   queue snapshots or missing replay never authorize an old percentage.
7. The live composer and past-session footer show used/usable context and
   exact/derived/approximate confidence only for a fresh available observation;
   stale/loading/unavailable states show no percentage. Latest valid manual,
   automatic, or unknown compaction remains visible and the responsive shell
   does not overflow.
8. Claude result usage is strictly validated before the existing per-turn
   usage event; malformed fields write no fake-zero event and multi-model
   totals are not attributed to an arbitrary first model.
9. Focused contract/server/DB/web tests, hostile review, isolated browser QA,
   production web build, and full `pnpm ci:check` pass before guarded landing.

## Risk and recovery

- Primary risks: confusing turn usage with current context, treating a
  rounded provider percentage as canonical, blocking FIFO indefinitely on a
  control request, accepting late observations after runtime replacement, or
  creating a second latest-snapshot truth outside conversation replay.
- Recovery: strict adapter mapping, bounded typed timeout, runtime/session
  identity fences, canonical event/outbox persistence, and deterministic replay
  all fail closed. Any failed invariant preserves this branch/worktree while
  landed `main` remains untouched.
