# DL-004: Exact independent-review workspace authority

Status: active

## Objective

Close the remaining bounded `WT-002` gap. Every independent contract reviewer
must start only after PC-SDK durably owns an exact detached checkout of the
target sealed commit and has positive Git, preparation, and readiness evidence
for that checkout. Terminal review, failed admission, override, shutdown, and
restart must converge through one positive retryable teardown door before a
verdict can authorize landing or a successor review can start.

## Durable review-workspace semantics

The workspace component must persist authority before `git worktree add` so a
crash can never leave an ownerless registered checkout. The record has one
closed lifecycle: reserved, provisioned, teardown-pending, destroyed. It binds
the full reviewer run ID; the historical `review-<last8>` name is presentation,
not cleanup authority. Exactly one current record owns a path and review run.

Provisioning is positive only when the exact path is registered once, the
registration is detached at the target sealed commit, `HEAD` equals that seal,
tracked/staged status is clean, the path resolves inside the real owned
worktree root, and repository identity matches the target producer and project.
The review run's Git receipt must name this checkout, not the builder path.

The project worktree profile applies to a write-capable reviewer. Setup and
readiness execute under the same repository guard and cancellation checks as a
builder. Empty command lists receive explicit no-command receipts. Missing,
failed, inherited, or builder-copied receipts are not reviewer authority.

Verdict processing may begin only after the reviewer is terminal and runtime
quiescent, its typed deliverable/contract passed, the target reservation and
seal still match, and the exact review workspace has not drifted to another
HEAD, attached branch, path, identity, registration, or tracked/staged state.
Teardown then removes only that detached checkout and proves both directory and
registration absence. Exact durable settlement is the barrier before approve
can land, reject can open Fix, override can complete, the marker can clear, or
a successor round can reserve.

## Recovery semantics

The production boot sequence re-drives unresolved review workspaces before
pending-review re-entry. Reserved-before-add converges from directory and
registration absence. Added-before-provision-receipt is inspected against the
durable authority and either positively adopted or preserved as drifted.
Terminal review cleanup retries until positive. Removal-before-row-settlement
re-proves absence and completes the exact CAS. A locked or unreadable checkout
retains the original reservation and prevents round burn or cross-cleanup.

## Acceptance criteria

1. No reviewer runtime mints without exact durable review-workspace authority,
   provision, checkout-specific Git, preparation, and readiness receipts.
2. Project/target/version/producer/reviewer/path/identity/seal/registration/
   detached HEAD/clean evidence is exact and revalidated after awaits.
3. Builder-copied, missing, malformed, stale, dirty, attached, moved-HEAD,
   retargeted-registration, aliased-path, or negative evidence refuses mint and
   verdict authority.
4. Failed setup/readiness starts no runtime and leaves exact cleanup truth.
5. A typed verdict cannot land or enter Fix until positive teardown settlement
   of its exact review workspace.
6. Successful remove exit alone is insufficient. Directory, registration,
   query, lock, identity, path, or CAS uncertainty stays retryable and visible.
7. Admission, terminal, kill, override, shutdown, and boot share one cleanup
   owner; concurrent observers cannot double-settle or clear a newer marker.
8. Crashes before add, after add, after provision receipt, after run insert,
   after terminal evidence, after removal, and before durable settlement all
   converge; a second boot is effect-idempotent.
9. A successor reviewer cannot reserve until the prior exact checkout settles;
   full-run-ID authority prevents last-eight-character collision cross-cleanup.
10. Existing UI shows honest exact provision/phase/verdict/cleanup evidence and
    explicit unavailable state. No new mutation or recovery-center door exists.
11. Existing full-review, landing, continuation, override, shutdown, recovery,
    and DL-003 matrices remain green.
12. Actual-path audit, `git diff --check`, three hostile reviews, full
    `pnpm ci:check`, sealed commit, guarded landing, ancestry/tree proof,
    post-merge gate, exact push/re-fetch, and worktree cleanup pass.
