# PI-001 — Provider-neutral project instructions

Status: complete

## Outcome

PC-SDK owns one repository instruction source, the root `AGENTS.md`, and
injects the same immutable session snapshot into Claude and Codex orchestrator
and specialist sessions. Provider-native project-instruction discovery must not
duplicate or override that snapshot.

## Scope

- Add an app-owned root `AGENTS.md` loader with explicit unavailable/invalid
  outcomes, bounded UTF-8 content, and a SHA-256 revision.
- Compose the snapshot with the existing orchestrator/specialist charter before
  the runtime adapter boundary.
- Disable Codex native project-document discovery per native session and retain
  the strict empty `instructionSources` receipt.
- Persist enough snapshot evidence to make re-mint/resume deterministic.
- Remove Claude-specific `CLAUDE.md` guidance from stock prompts.
- Add focused parity, safety, persistence, and Codex wire guards.

## Boundaries

- `docs/agent-runtime-architecture.md`
- `docs/architecture/boundaries.md`
- `docs/worktree-lifecycle.md`
- `docs/requirements.md`

## Acceptance

1. A root `AGENTS.md` is read once by PC-SDK and the same bytes/revision reach
   Claude and Codex for an equivalent session.
2. Codex returns no provider-native instruction sources because PC-SDK sets its
   project-document byte limit to zero.
3. Re-mint/resume retains the session's original instruction snapshot even if
   the file changes later; a new app session receives the new revision.
4. Missing `AGENTS.md` is an explicit empty snapshot; malformed, oversized, or
   non-canonical inputs fail closed without leaking file contents.
5. Specialists receive the same project snapshot plus their revisioned charter.
6. Focused tests and `pnpm ci:check` pass.
