# RS-001: Immutable orchestrator runtime selection

Status: active

## Objective

Implement the first bounded N3 invariant for the orchestrator: every newly
created app session carries one complete immutable runtime/account/model/effort
selection, every native identity is bound once from a positive adapter receipt,
and every later mint or resume routes only through that durable stamp. Prove the
contract with the Claude adapter before adding Codex or broader N3 surfaces.

so those requirements are not globally complete when this slice lands.

## Canonical decisions

`RuntimeSelection` contains non-empty `runtimeId`, `accountId`, and `model`,
plus an explicit effort union: selected value, supported-but-none, or
unavailable. Core code has no model or effort enum. The selected adapter/account
returns typed capabilities and model discovery, and validates again immediately
before create/resume.

A newly inserted session starts with a complete immutable selection and an
unbound native identity. The first exact adapter `session-started` receipt binds
the non-empty native ID. Repeated matching receipts are idempotent; a different,
empty, or wrong-mode identity fails closed. Runtime-observed model metadata can
never rewrite the selected model.

Legacy rows are `legacy-unavailable`. Their previous native ID may remain as
untrusted migration evidence, but provider labels or current defaults are never
promoted into a runtime/account selection. A legacy active row is ended during
migration so it cannot silently acquire today's defaults.

Resume validation happens before the transition. It requires a complete stamp,
a bound native ID, the exact registered adapter/account, positive native-resume
capability, and a currently supported model/effort selection. Failure leaves the
current active session, queue, and project default unchanged. A requested native
resume can never degrade into a clean start.

Account/model/effort changes create a new app session. Prior stamped sessions
remain resumable through their original account. Account switching compares the
requested account with the active session stamp rather than merely the mutable
project default.

## Acceptance criteria

1. Every new orchestrator session persists one complete adapter-validated
   runtime/account/model/effort stamp before work admission; DB guards reject
   incomplete or later-mutated stamps.
2. Migration never invents selection truth for legacy rows. Legacy transcripts
   remain readable, legacy active sessions are safely ended, and no legacy row
   can resume or accept new work.
3. Native identity changes only from unbound to one non-empty value on an exact
   positive created receipt. Native resume becomes confirmed only on a matching
   resumed receipt; conflicts, empty IDs, and late receipts write nothing and
   cannot fall back clean.
4. Runtime create, restart, prompt-revision remint, historical resume, and
   account A -> B -> resume A all consume the row stamp. Changing project,
   account, or orchestrator defaults cannot change an existing session's
   runtime/account/model/effort.
5. Duplicate runtime registration, unknown runtime/account, runtime/account
   mismatch, unavailable discovery, unsupported model/effort, unsupported
   native resume, and missing native identity return typed failures without an
   adapter call or alternate behavior/billing path.
6. Resume preflight finishes before atomic activation. Every negative or racing
   path preserves the current active session, queue, and project default; a
   successful selection change commits cancellation/end/default/new stamped row
   together.
7. Session summaries expose the complete selection, continuation provenance,
   native-ID presence only, and typed resume availability without native IDs or
   credential homes. Exact-shape guards reject malformed/extra selection data.
8. The existing account/session shell reflects the active session stamp,
   distinguishes legacy/unsupported/unavailable resume states, and never labels
   a clean start as a native resume or handoff.
9. Focused contract/DB/server/web tests, migration tests, adversarial review,
   production web build, and full `pnpm ci:check` pass before guarded landing.

## Risk and recovery

- Primary risks: resolving mutable defaults after session creation, treating
  capability support as proof of a specific resume, accepting a late/conflicting
  native identity, mutating the current session before resume preflight, or
  guessing a legacy account/runtime.
- Recovery: typed preflight stops before mutation; the DB enforces immutable
  stamps and bind-once identity; receipt mismatch quarantines the runtime; atomic
  transitions roll back completely; any failed invariant preserves this branch
  and worktree while landed `main` remains untouched.
