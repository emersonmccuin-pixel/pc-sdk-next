# RS-004: Provider-neutral subscription quota

Status: complete — sealed, awaiting guarded landing

## Objective

Replace the inherited Claude-shaped, best-effort usage meter with one durable
provider-neutral subscription-quota component. Runtime adapters report strict
native source observations; PC-SDK owns runtime/account attribution,
used/remaining normalization, freshness, persistence, publication, and the
browser projection. Context and per-turn token usage remain separate families.

## Requirements and boundaries

- Requirement IDs: `USE-001` through `USE-003`, plus the quota capability and
  provider-boundary portions of `RUN-001` and `ARCH-004`.
- Boundary documents: `docs/architecture/boundaries.md`,
  `docs/agent-runtime-architecture.md`, `docs/event-contract.md`, and
  `docs/worktree-lifecycle.md`.
- The usage/context component owns durable quota truth, normalization,
  confidence, staleness, and resource publication. An adapter owns credentials,
  native quota requests, native response parsing, and exact native-to-canonical
  source mapping. Composition resolves adapters by runtime; quota never selects
  or reroutes execution.

This slice does not claim Codex support, selector UI, quota-aware routing,
cross-runtime handoff, raw API billing, provider parity, a general usage
dashboard, or any change to session-context semantics.

## Canonical decisions

The adapter returns one strictly guarded `SubscriptionQuotaObservationBatch`
attributed to its exact runtime/account. Available batches declare `partial` or
`complete` coverage and contain stable dynamic window observations. Each source
observation retains its native semantic and normalized source fraction but does
not author the final used fraction. The app service derives `used => f` and
`remaining => 1 - f`, assigns `staleAt` from the component policy capped by a
known reset, and rejects contradictory, malformed, duplicate, old, or
mismatched evidence.

The durable snapshot is keyed by exact `(runtimeId, accountId)`, has a positive
monotonic revision, records the latest availability attempt, and retains each
last-good window's own `observedAt` and `staleAt`. A partial batch upserts only
named windows; a complete batch also removes positively absent windows. An
unavailable attempt changes availability without inventing or refreshing a
window. Retained windows therefore age honestly and cannot be made fresh by an
unrelated observation.

One current-state SQLite row stores the exact guarded snapshot JSON with its
identity/revision columns. Repository mutation and the matching global
`subscription-quota.changed` full-snapshot outbox row commit in one transaction.
HTTP reads the product table directly; boot does not hydrate truth from the
prunable outbox. Resource `entityId` equals the durable snapshot row's stable
app-owned ULID, while payload/store uniqueness is exact `(runtimeId, accountId)`;
`version` equals snapshot revision.

The generic scheduler owns timing, timeout, no-overlap, adapter resolution, and
service submission. The Claude adapter continues the proven OAuth acquisition
path but exclusively owns its URL, beta header, selected credential home, token
parsing, fetch, and native response mapping. Provider failures become closed
unavailable reason codes; raw exception text is logging-only. Passive SDK
events are strict partial batches and must match the immutable live selection
before they can enter the component.

The old ambiguous `UsageSnapshot`, runtime `rate-limit` event, `usage` resource,
and `/api/usage` route are replaced in one pass. Per-turn `RuntimeUsage` and chat
`usage` telemetry are intentionally unchanged. No compatibility wire remains.

## Acceptance criteria

1. Exact contracts reject extras, duplicate windows, malformed identities,
   non-finite/out-of-range fractions, unsafe times, invalid source algebra, and
   malformed capability/availability/coverage variants.
2. Equal account IDs under two runtimes remain distinct through adapter
   resolution, durable state, outbox identity, HTTP, websocket, browser store,
   and presentation.
3. Quota product truth survives complete outbox pruning and restart. A DB or
   outbox failure rolls back the whole transition and cannot leave memory/HTTP
   ahead of SQLite.
4. Complete batches clear positively absent windows; partial batches preserve
   them. Every successful observation refreshes only its covered windows even
   when values are unchanged. Failures preserve last-good values without
   refreshing them, mark availability honestly, and allow them to become stale.
5. The app service alone derives normalized used fraction and preserves source
   semantics. Remaining `0.25` presents as `0.75` used; no adapter can author a
   contradictory normalized value.
6. Claude acquisition/parsing is wholly adapter-local. OAuth utilization
   outside `0..100`, passive utilization outside `0..1`, missing/non-finite
   values, duplicate windows, or malformed native data never becomes zero or
   current quota evidence.
7. Polling is bounded and non-overlapping. Unknown runtime/account evidence
   never hits a provider. Pull and passive results are fenced to exact immutable
   runtime/account attribution; specialist-only passive events use the same
   component and never enter transcripts.
8. Malformed quota HTTP/resource payloads, wrong scope/project/entity key, or
   revision mismatch are rejected before cursor or store mutation. Epoch/live-
   reset re-prime heals state, while a slow older HTTP seed cannot overwrite a
   newer live revision.
9. The rail renders only reported dynamic windows, labels every number `% used`,
   exposes runtime/account and source/confidence semantics, shows stale and
   unavailable states without fabricated percentages, and remains visibly
   separate from session context.
10. Focused adversarial suites, migration/restart proof, source/path audits,
    production web build, isolated no-provider browser QA, independent hostile
    review, and full `pnpm ci:check` pass before sealing and guarded landing.

## Risk and recovery

- Primary risks: mistaking transport for truth, inventing provider scale or
  precision, cross-runtime account collision, refreshing an untouched window,
  stale HTTP regression, partial/full conflation, or accepting quota evidence
  from the wrong immutable selection.
- Recovery: all native ambiguity fails unavailable; DB plus outbox is atomic;
  revision and attribution guards reject stale/mismatched evidence; legacy rows
  are not promoted; failed gates preserve the feature worktree while `main`
  remains read-only.
