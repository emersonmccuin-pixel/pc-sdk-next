# CF-001: Canonical conversation persistence

Status: sealed and verified; guarded landing pending

## Objective

Replace the Claude-first split chat/delta wire with one provider-neutral,
server-sequenced conversation event path whose event row and live-publication
outbox entry commit atomically and whose live/replay/browser projections are
deterministic.

  outbox; timestamps are metadata; exact duplicate delivery is idempotent and

  retained as hidden legacy data and no new private reasoning content crosses

## Acceptance criteria

1. Every new conversation event has project/conversation/session sequence,
   item, optional turn/stream, optional delta index, and occurrence time; no
   provider-native message identifier exists in canonical contracts or browser
   sources.
2. Sequence allocation, event insert, and outbox insert are one SQLite
   transaction; concurrent writers cannot allocate the same sequence.
3. Live publication drains committed outbox rows in sequence and marks them
   only after fanout; a crash window is replay-safe and duplicate fanout is
   idempotent in the browser.
4. Visible deltas use the same sequenced persisted envelope and deterministic
   delta-index projection as stable events.
5. Exact redelivery does not change projection. Conflicting duplicate sequence
   or delta identity preserves the accepted projection and records an explicit
   integrity conflict.
6. Shuffled live delivery and replay produce the same complete state and
   rendered timeline; past-session viewing uses that same projector.
7. Existing private reasoning rows migrate to a hidden legacy kind; the Claude
   adapter emits no new thinking blocks/deltas into the canonical runtime seam.
8. Focused tests and `pnpm ci:check` pass.

## Risk and recovery

- Risks: migration of opaque historical JSON, high event volume from persisted
  deltas, duplicate publication around crash, and cross-layer contract drift.
- Rollback/preservation behavior: migration keeps all historical payloads;
  hidden reasoning rows are not deleted; any migration/test/landing uncertainty
  preserves the feature branch and worktree.
