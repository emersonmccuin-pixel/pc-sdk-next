## Evidence matrix and gate

Each row records the subject revision, fixture/state, viewport, interaction,
expected result, observed result, evidence kind, artifact or guard reference,
console/network result, and disposition. Evidence kinds are:

- `direct`: observed in the real production bundle through the browser;
- `guard-backed`: a deterministic lower-level test proves a state that is
  unsafe or needlessly artificial to manufacture through the browser;
- `unavailable`: the slice cannot establish the claim and carries it forward.

N1 passes only when:

1. preserved and current desktop/narrow shell captures are present and any
   material visual delta is either accepted-requirement-driven or recorded as a
   regression/product decision;
2. the current coherent journey proves project/session isolation, ordered
   canonical chat projection, durable controls, provider-neutral provenance,
   context/quota honesty, activity/transcript honesty, reload/reconnect
   equivalence, and responsive usability through direct or named guard-backed
   evidence;
3. no unexplained console error, unbounded horizontal overflow, leaked native
   session/attempt identity, or private reasoning is observed;
4. every stale BC-001 finding is marked closed, still-open, or superseded with
   current file/test evidence;
5. focused checks, production builds, full `pnpm ci:check`, fixture cleanup,
   independent hostile review, and guarded landing all pass.

A direct browser failure does not expand this slice into a fix. It blocks N1 or
creates a dependency-ordered behavior slice unless the failure is solely in the
test fixture.

  unreviewed implementation change.

  ambiguous evidence stays unavailable; a failed gate preserves this feature
  worktree while `main` remains read-only.
